# Documentación de Flujos de Operaciones del Sistema

## 1. Registro de Usuarios (Normal y Vendedor)

### Registro de Usuario Normal
**Flujo:** El usuario envía el formulario de registro desde la vista de login. El controlador JS intercepta el envío y hace una petición asíncrona a la API de autenticación. El backend valida los datos, hashea la contraseña y usa un pipeline asíncrono de Redis (cola) para procesar el registro rápidamente. Existe un fallback para hacer la inserción sincrónica en la base de datos si Redis falla. Al completarse, se envía un email de bienvenida.

*   **Archivos Frontend:**
    *   **Vista:** `src/views/login.view.php` (Contiene el formulario de registro)
    *   **Controlador JS:** `src/scripts/controllers/AuthController.js` (Maneja el envío del form)
*   **API/Rutas Backend:**
    *   **Lógica API:** `src/functions/auth_controller.php` (Maneja POST con `accion=registro`)
*   **Funciones/Controladores Backend:**
    *   `ValidationService::validarRegistro()` en `src/workers/Services/ValidationService.php` (Valida datos)
    *   `RedisConfig` en `src/workers/Config/RedisConfig.php` (Conexión a Redis)
    *   `MailService` en `src/functions/mail_service.php` (Envía email de bienvenida)
*   **Scripts/Workers de Base de Datos:**
    *   **Procedimiento DB:** `crearUsuario` (Usado directamente si falla Redis)
    *   **Worker Asíncrono:** `src/workers/Jobs/RegisterUserJob.php` (Consume la cola `cola:registros` de Redis para insertar en DB de forma asíncrona)

### Registro de Vendedor (Conviértete en Vendedor)
**Flujo:** Un usuario normal autenticado llena un wizard de 3 pasos con datos personales, ubicación y bancarios. El formulario se envía a un endpoint dedicado que ejecuta una transacción en DB para registrar al productor, asignarle el módulo "Mis Productos" y revocarle el módulo estándar "Vender".

*   **Archivos Frontend:**
    *   **Vista:** `src/views/registro_vendedor.view.php`
*   **API/Rutas Backend:**
    *   **Endpoint API:** `src/api/post_registro_vendedor.php` (Procesa el envío)
    *   **Controlador App:** `src/controllers/registro_vendedor.php` (Renderiza la vista)
*   **Funciones Backend:**
    *   `AuthHelper::protectRoute()` (Asegura que solo usuarios logueados accedan)
    *   Mapeo de conexión a DB.
*   **Scripts/Funciones de Base de Datos:**
    *   `crearProductor` (Inserta datos del vendedor)
    *   `asignarMenuUsuario` (Otorga acceso al menú de vendedor ID 10)
    *   `revocarMenuUsuario` (Revoca menú estándar ID 9)

## 2. Login

**Flujo:** El usuario ingresa credenciales. El controlador JS hace una petición a la API de Auth. El sistema busca el hash de la contraseña en la base de datos y lo verifica. Hay un fallback híbrido que busca en Redis si el usuario fue registrado recientemente vía la cola asíncrona. Si es exitoso, se genera un token JWT y se guarda en una cookie segura.

*   **Archivos Frontend:**
    *   **Vista:** `src/views/login.view.php`
    *   **Controlador JS:** `src/scripts/controllers/AuthController.js`
*   **API/Rutas Backend:**
    *   **Controlador App:** `src/controllers/login.php` (Redirige si ya está logueado, sino muestra vista)
    *   **Lógica API:** `src/functions/auth_controller.php` (Maneja POST con `accion=login`)
*   **Funciones Backend:**
    *   `AuthHelper::generateToken()` y `AuthHelper::setAuthCookie()` (`src/functions/auth_helper.php`)
    *   Conexión `RedisConfig` (para verificar logins híbridos de cuentas recién creadas que aún no se sincronizan)
*   **Scripts/Funciones de Base de Datos:**
    *   `obtenerHashLogin` (Trae el hash de la contraseña)
    *   `obtenerUsuarioPorEmail` (Recupera info core para armar el token JWT)

## 3. Recuperación de Contraseña / Validación de Token

**Flujo:** El usuario solicita resetear su password. La API genera un token OTP con tiempo de expiración, lo guarda y lo envía por email vía `MailService`. El usuario recibe el OTP, lo envía junto con su nueva contraseña, y el sistema verifica el token antes de hashear y actualizar la clave en la DB.

*   **Archivos Frontend:**
    *   **Vista:** `src/views/recuperar.view.php`
    *   **Servicio JS:** `src/scripts/services/PasswordRecoveryService.js` (Maneja la API para pedir y confirmar código)
*   **API/Rutas Backend:**
    *   **Controlador App:** `src/controllers/recuperar.php` (Muestra vista)
    *   **Endpoint API:** `src/api/recuperar.php` (Maneja POST con `accion=solicitar` y `accion=confirmar`)
*   **Funciones Backend:**
    *   `MailService::sendPasswordRecoveryEmail()` (`src/functions/mail_service.php`)
*   **Scripts/Funciones de Base de Datos:**
    *   `crearResetToken` (Genera OTP y guarda expiración)
    *   `obtenerNombreUsuarioPorEmail` (Para personalizar correo)
    *   `validarResetToken` (Valida el token contra DB)
    *   `actualizarPassword` (Guarda la nueva contraseña hasheada)

## 4. Operaciones CRUD de Administración

**Flujo:** Los administradores acceden al panel central para manejar usuarios, productos, menús y tablas maestras (categorías, países, bancos). Las interacciones en la UI llaman a un endpoint central que funciona como un multiplexor, mapeando la `entidad` y `accion` hacia funciones dinámicas en la base de datos.

*   **Archivos Frontend:**
    *   **Vista:** `src/views/admin_dashboard.view.php`
    *   **Controlador JS:** `src/scripts/admin_crud.js` (Maneja modales, tablas dinámicas, filtros y estado)
*   **API/Rutas Backend:**
    *   **Controlador App:** `src/controllers/admin_dashboard.php` (Renderiza el panel de admin)
    *   **Endpoint API:** `src/api/admin_crud.php` (Multiplexor para todas las acciones: list_users, toggle_user, assign_menu, y CRUD genérico)
*   **Funciones Backend:**
    *   `AuthHelper::checkAccess(8)` (Valida que el usuario tenga el ID de menú de admin)
    *   `Database::getInstance()->gestionarCRUDAdmin()` (Mapeo dinámico para manejar tablas maestras basado en el tipo de entidad)
*   **Scripts/Funciones de Base de Datos:**
    *   **Procedimientos especializados:** `listarUsuariosAdmin`, `listarProductosAdmin`, `toggleUsuarioActivo`, `toggleProductoActivo`, `listarMenusUsuario`, `asignarMenuUsuario`, `revocarMenuUsuario`.
    *   **Procedimientos genéricos:** Resueltos dinámicamente dentro de la clase de Base de datos, usando funciones como `fun_softdel_*`.
